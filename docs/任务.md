## 已完成任务 2：跑通第一个 B200 PTX task

**状态：已完成（2026-08-19）。** Oracle 正例、负例和真实 Codex Agent
均已通过预定验收。

目标不是马上做性能榜，而是把第一条 GPU 链路跑通：

```text
instruction.md
    -> Agent 或 Oracle 生成 /app/kernel.ptx
    -> Harbor Singularity 环境透传 NVIDIA GPU
    -> tests/verify_ptx.py 通过 CUDA Driver API 加载并执行 PTX
    -> tests/test.sh 写入 reward 0 或 1
    -> Harbor 保存 trial 结果
```

任务目录是 `tasks/ptx-add-one/`。kernel 接口固定为：

```text
add_one(const int32_t* input, int32_t* output, uint32_t n)
```

它只验证 PTX 正确性与 Harbor GPU 基础设施，不测性能，因此还不是正式的
benchmark-quality kernel 题目。

### 服务器与 Harbor 的边界

- `catalyst-b200`、SSH 和空闲 GPU 选择属于运行编排，不写进 task。
- task 只在 `task.toml` 中声明 `gpus = 1` 和 `gpu_types = ["B200"]`。
- 远端 Docker daemon 对当前用户不可用，因此使用 Singularity/Apptainer。
- 远端 Harbor `0.13.2` 的 Singularity 后端原本没有 `--nv`，且会在 `/app`
  尚不存在时提前执行 `--pwd /app`。可复现修复保存在
  `patches/harbor/0001-singularity-nvidia-workdir.patch`。

## 已完成任务 1：跑通 Harbor 最小任务闭环

## 为什么先做这个

按照卓明在录音里的要求，当前第一步是先理解 Harbor：

- 一个 task 怎么加入 Harbor；
- Agent 在什么环境里看到什么、执行什么；
- Agent 提交结果后，verifier 怎么检查并产生分数。

这一阶段只验证 Harbor 的基本闭环，不做 PTX、不接 FlashInfer-Bench，也不设计正式 kernel 题库。

## 完成目标

创建一个最简单的 `harbor-smoke` 任务：Agent 需要在指定路径生成一个文本文件，verifier 检查文件内容并给出 `0` 或 `1` 的 reward。

最终必须亲自看懂并跑通下面这条链路：

```text
instruction.md
    -> Harbor 启动隔离环境
    -> Agent 在环境中完成任务
    -> tests/test.sh 执行隐藏检查
    -> /logs/verifier/reward.txt
    -> Harbor 保存 trial 结果和日志
```

## 实现步骤

### 1. 安装并确认 Harbor CLI

**状态：已完成（2026-08-18）。** 实际安装与命令检查记录见
[`setup/harbor-cli.md`](setup/harbor-cli.md)。

参考：

- <https://github.com/harbor-framework/harbor>
- <https://www.harborframework.com/docs/tasks>

完成以下检查：

```bash
harbor --help
harbor run --help
harbor task --help
```

如果实际版本没有 `harbor task`，以 `harbor --help` 显示的当前命令为准，并把实际命令记录下来，不要猜 CLI。

本机安装的 Harbor `0.21.0` 确实提供 `harbor task`；当前创建任务命令为：

```bash
harbor task init [name] --tasks-dir <path>
```

### 2. 创建最小任务目录

目标目录：

```text
tasks/harbor-smoke/
├── instruction.md
├── task.toml
├── environment/
│   └── Dockerfile
├── solution/
│   └── solve.sh
└── tests/
    └── test.sh
```

任务内容固定为：

```text
要求 Agent 创建 /app/answer.txt，文件内容必须恰好为 harbor-ok 加一个换行。
```

各文件职责：

- `instruction.md`：只告诉 Agent 要产生什么结果，不泄露 verifier 实现。
- `task.toml`：声明任务 metadata、Agent 超时和 verifier 超时。
- `environment/Dockerfile`：提供最小 Linux 环境和 `/app` 工作目录。
- `solution/solve.sh`：Oracle 使用的标准答案。
- `tests/test.sh`：检查 `/app/answer.txt`，把最终分数写入 `/logs/verifier/reward.txt`。

### 3. 先用 Oracle 验证任务本身

运行 Harbor 的 Oracle agent。实际命令以当前 CLI 帮助为准，预期形式为：

```bash
harbor run -p tasks/harbor-smoke -a oracle
```

必须确认：

- 环境能够成功构建；
- `solution/solve.sh` 被执行；
- verifier 被执行；
- 最终 reward 为 `1`；
- 能找到 Harbor 保存的 trial 日志和结果文件。

如果 Oracle 不能得到 `1`，先修任务定义，暂时不要运行真实模型。

### 4. 再运行一个真实 Agent

从 `harbor run --help` 中选择当前已经可用的一个 coding agent。让它完成同一个任务，并确认：

- Agent 收到了 `instruction.md`；
- Agent 能在容器内执行命令和写文件；
- Agent 运行期间看不到标准答案；
- Agent 完成后 verifier 才开始评分；
- reward 为 `1`。

不要在本任务中比较多个模型，也不要做 leaderboard。
